# Task-aware paid merchant

Platform durability: files are fsynced before atomic rename. POSIX also fsyncs
the parent directory; Windows does not support directory-handle fsync and uses
file fsync/rename for process-crash recovery only. No Windows power-loss guarantee
is claimed. Unknown payment outcomes and crash locks still fail closed.

The task SDK (`backend/hedera/lib/task-client.mjs`) requests a merchant-signed quote, validates deployment/chain/asset identity and quote signature, reserves under the current epoch, then submits the 96-byte authorization with a short-lived worker signature. Logical step identity excludes the worker/epoch. Current worker or owner signatures authenticate result access; old workers lose retrieval authority after reassignment. The owner remains the trust root.

`task-merchant.mjs` validates the manifest, task merchant, fixed route/price, canonical request hash, amount and reservation attempt. It submits `executeTransfer` only against an observed reservation and confirms a successful receipt plus the matching Paid event. Reconciliation uses contract operation state and Paid logs. Contract runtime identity is pinned; the reviewed contract itself verifies exact payer debit and merchant credit. New tests independently read the merchant token balance. This phase produces local EVM evidence, not fresh Hedera HTS consensus-child-record verification.

`operation-store.mjs` persists intent and submitting state before external calls, then confirmed receipt, deterministic immutable result and SHA-256 integrity hash. Writes fsync file and directory around atomic rename; the storage filesystem must support those guarantees. A per-operation exclusive lock serializes writers across processes. Process-crash locks fail closed: stop all writers and reconcile the operation/transaction before removing a stale lock. Never clear state as a retry strategy. An unknown submission or stale unpaid read cannot create another transaction. If all local records of a paid operation are lost, the client surfaces an owner decision rather than reconstructing an unprovable original artifact or repurchasing it. Results are retained without an automatic expiry policy; backups are required.

The reference deterministic dataset is an echoed, canonical artifact, not an external research provider or a real model output. Production artifact builders must be deterministic and version-pinned. Local state is private filesystem data but is not encrypted; encrypted checkpoints and public-metadata controls are separate work. The current protocol uses EOA EIP-191 signatures and a custom signed HTTP adapter; general x402 client interoperability, smart-account signature validation and public facilitator admission are not claimed. The original Phase-0 server is preserved separately.

Install all modules (`npm run setup`) and compile (`npm run contracts:compile`) before backend integration tests; they use the contracts module's Ganache fixtures and identity validator. Tests cover post-payment response failure, merchant restart, replacement access, old-worker rejection, changed-body/price conflicts, result reuse, missing-state failure, unknown outcomes, SDK reservation and a separate task making progress. No live funds are moved by tests.

To start the optional live testnet service, provide the dedicated merchant key through `HEDERA_MERCHANT_PRIVATE_KEY`, then run `npm run task:serve --prefix backend`. It validates the historical pinned treasury before listening at localhost:4023; it does not start automatically. `/quote` and `/purchase` accept POST JSON; requests are capped at 64 KiB. A valid purchase can spend testnet funds. The reference price is 20,000 USDC base units (0.02 test USDC), route `/dataset`. `.merchant-state/` is ignored, not disposable cache. RPC bootstrap and all live behavior still require separate rehearsal. Chain finality/reorg policy is not production-qualified; current tests use an ephemeral local chain and receipt confirmation.

The SDK now independently validates result hashes, confirmed operation state and the returned transaction's matching Paid event before checkpoint use. The reference signing service serializes submissions across tasks; deploy only one signing service instance per merchant key. See [RUNNER.md](RUNNER.md) for the local checkpointed handoff prototype and concurrency limits.

Live hardening now adds confirmation-depth policy, receipt-based reconciliation, bounded log pages, testnet fee ceilings, HTTPS enforcement and a signer-process lock. Testnet keys are restored and preflight passes. The bounded Hedera live check now passes: exactly 0.02 test USDC debited/credited, with the original result/receipt reused on replay. Public evidence is in `backend/hedera/evidence/task-aware-live-proof.json`. See [MERCHANT_LIVE_SETUP.md](MERCHANT_LIVE_SETUP.md) for the exact setup and remaining release boundaries.
